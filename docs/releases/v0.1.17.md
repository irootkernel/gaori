# Gaori v0.1.17

Gaori v0.1.17 simplifies CLI version identity and modernizes the source-distributed skills for safer host integration and complete installation.

## Changed

- Gaori skills load conditional references and follow host waiting rules; installation copies complete skill trees and refuses existing targets.
- CLI version JSON now contains only `name` and the `v`-prefixed `version`; the `commit` field has been removed.

## Compatibility

- Consumers of CLI version JSON must stop relying on `commit`; the object now contains exactly `name` and `version`. Human version output retains one `v` prefix, and MCP initialization retains its existing internal version representation.
- Development producer manifests continue to bind each executable to the full committed SHA and checksum independently of the CLI version payload.
- Install the complete `use-gaori` directory with all six references. `use-gaori-status` remains independently installable, and both installers refuse an existing file, directory, or symlink target.
- Command exit status remains authoritative. Parser selection, tag matching, raw-log preservation, derived-evidence redaction, and artifact layouts retain their existing contracts.

## Verification

- Release qualification uses the full repository `make test` gate: formatting, lint, vet, guardrails, build, race-enabled unit and integration tests, and black-box E2E checks.
- Independent release QA exercises version identity, MCP compatibility, skill behavior, distribution safety, and documentation consistency. Its bounded confirmation repeats the complete retained scenario inventory after the Procedure guidance correction.
- Exact-release installation is checked with isolated `make install` and `make install-toolchain`, human and JSON version output, and resolver selection.

## Known limitations

- Original raw logs remain unredacted and may contain sensitive values; rule proposals remain run-local until explicitly reviewed and promoted.
- `dart-test`, `patrol`, `dotnet-test`, and `gradle-test` remain Experimental under the parser support matrix.
- The development producer requires a committed `Unreleased` changelog heading and rejects source symlinks and submodules. Opening the next development cycle is separate from stable publication.
- Aquarium manager enrollment, host hooks, production activation, and MCP registration are separate operations and are not established by this release.
- Verification is local on Darwin arm64. Unix process-group and signal guarantees remain platform-specific; no bundled cross-platform release workflow is provided.
