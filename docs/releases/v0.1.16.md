# Gaori v0.1.16

Gaori v0.1.16 adds a committed-source Aquarium development producer, aligns CLI version identity, and clarifies asynchronous MCP guidance.

## Added

- An Aquarium development producer builds clean local `main` commits in isolation and reports executable version, commit, and checksum metadata.

## Changed

- CLI version JSON uses a `v`-prefixed version and includes the selected binary's commit identity.
- The `use-gaori` skill and README agent template prefer asynchronous MCP start and terminal awaiting, check CLI availability independently, and preserve pending awaits during timing queries.

## Compatibility

- Consumers of CLI version JSON must accept the leading `v` in `version` and the additional `commit` field. Human version output retains one `v` prefix; MCP initialization retains its existing internal version representation.
- Development manifests bind the executable to the full committed SHA and its checksum. Other build forms retain their existing commit metadata provenance.
- Command exit status remains authoritative. Parser selection, tag matching, raw-log preservation, derived-evidence redaction, and artifact layouts retain their existing contracts.

## Verification

- Release qualification uses the full repository `make test` gate: formatting, lint, vet, guardrails, build, race-enabled unit and integration tests, and black-box E2E checks.
- Independent release QA exercises the committed candidate's changed behavior and source-distributed guidance. The bounded confirmation repeats its complete retained scenario inventory after the guidance correction.
- Exact-release installation is checked with isolated `make install` and `make install-toolchain`, human and JSON version output, commit identity, and resolver selection.

## Known limitations

- Original raw logs remain unredacted and may contain sensitive values; rule proposals remain run-local until explicitly reviewed and promoted.
- `dart-test`, `patrol`, `dotnet-test`, and `gradle-test` remain Experimental under the parser support matrix.
- The development producer requires a committed `Unreleased` changelog heading and rejects source symlinks and submodules. Opening the next development cycle is separate from stable publication.
- Aquarium manager enrollment, host hooks, production activation, and MCP registration are separate operations and are not established by this release.
- Verification is local on Darwin arm64. Unix process-group and signal guarantees remain platform-specific; no bundled cross-platform release workflow is provided.
