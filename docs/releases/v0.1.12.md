# Gaori v0.1.12

Gaori v0.1.12 adds the first supported release of the post-v0.1.11 CLI usability, portable configuration, verified rule-proposal, and session-local MCP work while preserving command-result authority and existing artifact contracts.

## Added

- Built-in successful help for the root command, every primary command, and every rules subcommand.
- `gaori config check` for side-effect-free validation of schema-v2 config and every stored project rule.
- Position-independent global options before the ad-hoc child boundary and an explicit `--timeout-sec` for tagged ad-hoc runs.
- Unambiguous `summary_markdown`, `summary_json`, and `extractor_status` console JSON fields while retaining the previous aliases.
- `rules propose --summary <summary.json> --failure <failure-id>` with adjacent raw-log, checksum, line, and byte-span verification.
- A session-local STDIO MCP server with asynchronous start, get, revision wait, explicit cancel, and bounded excerpt tools.
- A portable project policy that permits reviewed `.gaori/tester.yaml` and direct `.gaori/tester/rules/*.yaml` files in source control while all other Gaori state remains local.

## Safety and hardening

- Summary-based proposals establish the complete raw-log checksum and capture only the selected bounded failure span in one stream.
- MCP validates explicit timeout bounds and rejects null values, truncated transport input, unsafe invocation lookup data, and stale, replaced, relocated, or oversized excerpt evidence.
- MCP shutdown and explicit cancellation propagate to child process groups. An execution context canceled before process creation now finishes as `killed` with exit `137` without starting the child command.
- Source builds require Go 1.26.6 or newer so the standard-library toolchain includes the required vulnerability fixes.

## Compatibility

- These new command and MCP surfaces start with v0.1.12; the published v0.1.11 binary does not provide them.
- Config schema v2, summary/status artifact schemas, watcher-hash inputs, parser selection, redaction boundaries, and authoritative command exit behavior remain unchanged.
- Existing console JSON `summary` and `extractor` fields remain compatibility aliases.
- MCP invocation state is ephemeral to one attached server process. Final filesystem artifacts remain the durable integration boundary.

## Verification

- Full repository `make test` gate, including formatting, lint, vet, guardrails, unit, integration, and E2E tests.
- Race-enabled runner and CLI tests, including pre-start cancellation and MCP lifecycle coverage.
- Human and JSON v0.1.12 version output from the built binary.
- `govulncheck ./...` with no reachable vulnerabilities.
- `git diff --check` and release-version reference review.

## Known limitations

- Original raw logs remain unredacted and may contain sensitive values.
- Rule proposals remain local until an operator reviews and explicitly creates or updates an active rule.
- MCP does not provide a daemon, durable job ledger, restart recovery, workflow authority, or acceptance state.
- The repository has no bundled cross-platform release workflow. Platform-neutral behavior is tested locally with additional Unix-specific process-group and signal coverage.
