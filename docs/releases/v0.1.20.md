# Gaori v0.1.20

Gaori v0.1.20 analyzes complete raw logs across execution, import, detection and authoring surfaces.

### Changed

- Analyze complete raw logs in CLI/MCP runs, `summarize`, `parsers detect`, `rules test` and `config check --sample`, finding failures before the final 256 KiB without size-only degradation while memory grows with log size;
  legacy `rules propose --raw-log` accepts sources of any size and limits only its selected span to 256 KiB.

### Fixed

- Status signature hashes now match the published summary when a failure or warning signature contains invalid UTF-8, so summary-based proposals and run insights no longer reject those runs for a hash mismatch.

## Compatibility and limitations

- Analysis memory grows with input size; complete-log analysis has no fixed-memory guarantee.
- Legacy raw-log proposals still limit the selected span to 256 KiB; configuration and stored/imported rule YAML limits remain unchanged.
- Command exit status remains authoritative; parsers and rules describe evidence only.
- Original raw logs remain unredacted; surfaced summaries and excerpts retain redaction and output limits.
- Rule proposals remain run-local until reviewed and promoted.
- Binary installation does not activate source-distributed skills or register MCP.
- Verification is local on Darwin arm64; Linux resource scaling remains unmeasured.

## Verification policy

- Full release qualification requires the repository `make test` gate: formatting, lint, vet, guardrails, build, race-enabled unit and integration tests, and black-box E2E.
- Independent release QA covers the complete release delta with fresh local offline scenarios.
- Isolated build, installation, toolchain resolver, and human/JSON version identity are checked before publication.
- The separate finite resource smoke is outside `make test`; its existing source observations remain bounded to their recorded candidate and host.
