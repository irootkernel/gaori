# Gaori v0.1.15

Gaori v0.1.15 adds deterministic parser discovery and Dart/Patrol extraction, artifact-derived run insights, and broader fail-closed evidence and path hardening while preserving the executed command's authority over pass or fail.

## Added

- A code-owned JSON parser catalog through `gaori --json parsers catalog`, with deterministic metadata for every registered parser label.
- Experimental `dart-test` and `patrol` parsers with bounded, fixture-backed failure extraction.
- Read-only historical command statistics and caller-elapsed estimates through CLI and MCP.
- An independently installable `use-gaori-status` skill that delegates calculations to Gaori and does not start, mutate, cancel, or clean runs.

## Reliability and safety

- Summary-based rule proposals reject missing, stale, symlinked, relocated, or metadata-inconsistent evidence.
- Artifact creation, standalone directory allocation, cleanup selection, and excerpt access fail closed across traversal, collision, stale-evidence, and external-symlink boundaries.
- Invalid run, command, rule, parser, and failure identifiers fail before command execution or artifact writes.
- Large and noisy logs retain complete raw evidence while bounded tails, failures, warnings, summaries, status artifacts, and excerpts remain within their contracts.
- Specialized parser misses remain `no_match` for passing commands and `degraded` for failed, timed-out, or killed commands without generic fallback or result changes.
- MCP lifecycle, cancellation, EOF, signal shutdown, revision waits, and bounded evidence behavior have expanded built-binary coverage.

## Compatibility

- The parser catalog is JSON-only and does not load project configuration, execute commands, create artifacts, or select a parser.
- Run insights read validated completed standalone artifacts. They do not inspect raw logs, execute commands, write state, or grant workflow, review, release, or acceptance authority.
- Existing parser labels, command-result semantics, artifact layouts, raw-log preservation, redaction boundaries, and rule-selection behavior remain unchanged.
- The source-distributed `use-gaori` guidance prefers one terminal await or one host-native pending handle for long MCP calls while retaining bounded observation when required by the host.

## Verification

- The full repository `make test` gate passed, including formatting, lint, vet, guardrails, build, race-enabled unit and integration tests, and black-box E2E tests.
- Release qualification includes isolated `make install` and `make install-toolchain` execution plus human and JSON version checks for the exact release candidate.
- Documentation contracts, parser fixtures, artifact containment, collision behavior, cleanup safety, rule lifecycle, MCP lifecycle, and documented CLI workflows are covered by the repository gate.

## Known limitations

- Original raw logs remain unredacted and may contain sensitive values.
- Rule proposals remain run-local until explicitly reviewed and promoted.
- `dart-test`, `patrol`, `dotnet-test`, and `gradle-test` remain Experimental under the parser support matrix.
- Historical estimates are factual summaries of retained matching evidence, not forecasts, deadlines, or test-gate decisions.
- The repository has no bundled cross-platform release workflow. Unix-specific process-group and signal guarantees remain platform-specific.
