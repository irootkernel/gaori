# Gaori v0.1.8

Gaori v0.1.8 lets tagged ad-hoc test commands select an existing built-in parser explicitly, so coding agents and operators can compact dynamically chosen test output without predeclaring every narrow command in `.gaori/tester.yaml`.

## Highlights

- Adds `gaori run --parser <label> --tag <tag> [--tag <tag> ...] -- <command...>` for ad-hoc execution.
- Supports the existing `generic`, `go-test`, `pytest`, `vitest`, and `playwright` parser labels without adding automatic parser detection.
- Keeps `generic` as the default when an ad-hoc run omits `--parser`.
- Applies existing project rules by exact parser match plus canonical all-tags matching.
- Adds coding-agent guidance for reading compact summaries and bounded excerpts before sensitive raw logs.

## Safety and compatibility

- Configured commands continue to use only the parser declared in `.gaori/tester.yaml`; `--parser` cannot override them.
- Missing, empty, repeated, or unsupported parser values fail with config exit code `2` before child execution or completed evidence creation.
- Arguments after the ad-hoc `--` boundary, including a child argument named `--parser`, are passed through unchanged.
- Existing tagged ad-hoc commands without `--parser` remain compatible and continue to use `generic`.
- Specialized parser misses do not fall back to generic extraction and never change the child command's authoritative result.
- Config schema, artifact layout, status values, watcher hashes, redaction boundaries, timeout/interruption behavior, and exit-code authority are unchanged.
- The selected parser continues to be recorded in `summary.json`; human console, console JSON, summary Markdown, and status JSON shapes are unchanged.

## Known limitations

- Ad-hoc runs still require at least one tag and an explicit `--` command boundary when `--parser` is selected.
- Raw logs preserve original evidence and may contain unredacted values. Redaction applies only to derived surfaced artifacts.
- Rule proposals remain local until a maintainer explicitly reviews and promotes them.
- Platform-neutral behavior is tested across the Go suite, with stronger process-group and signal guarantees on Unix than on non-Unix platforms.
