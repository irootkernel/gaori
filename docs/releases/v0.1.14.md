# Gaori v0.1.14

Gaori v0.1.14 adds event-driven terminal waiting to the local STDIO MCP interface so attached coding agents can wait for a run to finish without process polling or repeated unchanged observations.

## Added

- Read-only, idempotent MCP `await_run`, which accepts only a session-local `invocation_id` and returns the authoritative terminal snapshot.
- Host guidance for choosing one uninterrupted terminal await only when the MCP tool-call deadline exceeds the longest expected command plus evidence finalization.
- Source-distributed `use-gaori` guidance that falls back to `get_run` or bounded `wait_run` observation when host deadline capacity is unavailable or inadequate.

## Reliability and safety

- `await_run` waits on the invocation's completion event and has no Gaori-owned timeout.
- Cancelling or timing out an await request cancels only that waiter. It does not cancel the command, set `cancellation_requested`, or prevent a later await of the same invocation.
- Multiple concurrent awaiters and repeated awaits of a finished invocation return the same final revision and command result.
- Server shutdown owns cancellation of active runs and drains pending terminal waiters without coupling request cancellation to command cancellation.
- Clean EOF still exits `0`; SIGINT and SIGTERM still exit `130` and `143`; a command killed by MCP shutdown retains the distinct authoritative result `killed` with exit `137` when evidence materialization succeeds.

## Compatibility

- The existing seven MCP tools remain available. `wait_run` remains the bounded phase/revision interface with optional `timeout_ms`; `await_run` is terminal-only and does not accept timeout fields.
- MCP invocation state remains session-local. Disconnecting cancels active runs, and a new server cannot reattach to an old invocation ID.
- Command status and exit code remain authoritative. Awaiting does not change parser, rule, summary, artifact, redaction, or raw-log semantics.
- Gaori remains an optional evidence-compression adapter, not a test gate, workflow authority, review authority, daemon, durable task ledger, or restart-recovery service.

## Known limitations

- `await_run` depends on the attached host keeping one MCP request alive. Use bounded observation when the effective host deadline cannot safely cover the command and evidence finalization.
- MCP state is not durable across disconnects or server restarts. Completed standalone artifacts may be rediscovered, but invocation state cannot be recovered.
- Original raw logs remain unredacted and may contain sensitive values.
- `dotnet-test` and `gradle-test` remain Experimental under the parser support matrix.
- The repository has no bundled cross-platform release workflow. Unix-specific process-group and signal guarantees remain platform-specific.
