# Gaori v0.1.9

Gaori v0.1.9 adds fixture-backed failure extraction for test frameworks used across the current consumer projects and lets existing raw logs select their parser explicitly.

## Added

- Built-in `ginkgo`, `godog`, `cargo-test`, `flutter-test`, `bun-test`, and `node-test` parser labels.
- `gaori summarize --parser <label> ...`, with the same exact parser and all-tag rule selection used by run commands.
- Ginkgo, Godog, Cargo test, Flutter test, Bun test, and Node.js fixture coverage, including file, line, and test-name extraction.

## Improved

- `go-test` recognizes indented subtest failures, build failures, panics, and data-race reports while suppressing duplicate parent subtests.
- Parser matching ignores ANSI control sequences without modifying preserved raw evidence or raw spans.
- Existing Vitest and Playwright matching benefits from the same ANSI-normalized parser input.

## Compatibility

- Config schema remains version 2.
- Configured commands still select exactly one parser; no automatic parser detection, multi-parser mode, or generic fallback was added.
- The executed command's exit code remains authoritative for `run`. Parser evidence never changes command truth.
- `summarize` still exits `0` when artifact generation succeeds; its inferred status and exit code describe the imported log rather than an observed command execution.

## Known limitations

- Project-specific output such as custom Godot runners and Patrol wrappers still requires local extraction rules when no built-in format applies.
- Original raw logs remain unredacted and may contain sensitive values.
- `.gaori/` configuration, rules, proposals, and evidence remain local-only state.
- This release does not add release, install, review-acceptance, workflow, or runtime-activation authority to Gaori.
