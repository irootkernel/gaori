# Gaori v0.1.13

Gaori v0.1.13 expands read-only evidence and parser discovery, adds bounded redaction measurement, and records parser support maturity explicitly while preserving command-result authority and existing artifact schemas.

## Added

- `gaori parsers list` and `gaori parsers detect <raw-log>` for bounded, side-effect-free parser discovery that reports candidates without selecting a parser or adding fallback.
- `gaori runs list` and MCP `list_runs` for read-only discovery of completed standalone evidence with shared selectors, fail-closed validation, record limits, and response byte bounds.
- `gaori config check --sample <raw-log>` for ordered per-pattern redaction match and replaced-byte counts without surfacing matched text or pattern definitions.
- Built-in Jest, RSpec, `dotnet test`, and Gradle parser labels, bringing the shared registry to fifteen available labels.
- Rule-proposal listing and lookup through `rules proposals` and `rules show --proposal <name>`.
- A parser support matrix that separates runtime label availability from support maturity. Thirteen labels are Supported; `dotnet-test` and `gradle-test` are Experimental.

## Safety and hardening

- Parser detection scans only the final bounded complete-line window, rejects missing or special files before reading, and never emits raw-log content.
- Standalone evidence listing validates status artifacts against their directory layout and fails closed on unsafe paths, malformed evidence, symlinks, and special files.
- MCP listing bounds the complete serialized response, including its structured and text representations, and never exposes invocation IDs or raw-log contents.
- Config, rule, and proposal discovery reject non-regular files and unsafe filesystem entries.
- Redaction sampling remains read-only, is capped at 256 KiB, reports patterns by position, and fails closed instead of returning partial coverage.

## Compatibility

- All fifteen parser labels remain selectable through the same config, rule, run, summarize, list, and detect paths. Support tiers are documentation metadata and do not change CLI or artifact schemas.
- Specialized parsers still never fall back to `generic`. Parser matches, misses, and support tiers never change the executed command's authoritative result.
- `list_runs` is a stateless view of completed evidence, not a durable job ledger or restart-recovery mechanism. Existing MCP invocation state remains session-local.
- Existing config schema v2, summary/status artifacts, watcher-hash inputs, and console JSON compatibility aliases remain unchanged.

## Known limitations

- `dotnet-test` is Experimental because a real `dotnet test` failing log has not yet been validated.
- `gradle-test` is Experimental because Gradle 9.1 default concise output exposed `BookTest.java:10` but the parser did not retain that file and line.
- Original raw logs remain unredacted and may contain sensitive values.
- Rule proposals remain local until an operator reviews and explicitly creates or updates an active rule.
- MCP does not provide a daemon, durable job ledger, restart recovery, workflow authority, or acceptance state.
- The repository has no bundled cross-platform release workflow. Cross-compilation does not establish Linux or Windows runtime behavior, and Unix-specific process-group and signal guarantees remain platform-specific.
