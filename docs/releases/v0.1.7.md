# Gaori v0.1.7

Gaori v0.1.7 adds reusable coding-agent guidance for projects that adopt Gaori while preserving the v0.1.6 CLI, configuration, artifact, and evidence contracts.

## Highlights

- Adds one shared `AGENTS.md` or `CLAUDE.md` template for project-specific Gaori test gates.
- Directs coding agents to verify the pinned Gaori version and fail closed when the binary or local configuration is unavailable.
- Keeps command exit status separate from extraction quality and guides agents to inspect bounded summaries before sensitive raw logs.
- Documents local `.gaori/` Git hygiene and the evidence fields agents should include in completion reports.
- Reinforces that Gaori evidence does not grant review acceptance, final acceptance, release, or runtime-activation authority.

## Compatibility notes

- There are no CLI, config schema, parser, rule, artifact-layout, status-hash, or exit-semantics changes from v0.1.6.
- Existing schema-v2 project configuration and toolchain metadata remain compatible after updating `gaori.cli_version` to `0.1.7`.
- Projects may adopt the new coding-agent template independently of their runtime integration.

## Known limitations

- Raw logs preserve original evidence and may contain unredacted values. Redaction applies only to derived surfaced artifacts.
- Rule proposals remain local until a maintainer explicitly reviews and promotes them.
- Platform-neutral behavior is tested across the Go suite, with stronger process-group and signal guarantees on Unix than on non-Unix platforms.
